# Отчёт по лабораторной работе №1

## Описание процесса

Я выбрала процесс "Регистрация пациента в клинике". Там участвуют пациент, регистратор, медсестра и врач. Пациент приходит, регистратор проверяет документы и смотрит, первый раз человек в клинике или нет — если первый раз, создаётся новая карта, если нет — находится старая. Пока идёт оформление документов, медсестра параллельно измеряет давление и температуру. Дальше регистратор проверяет, есть ли свободный талон к врачу: если есть — записывает на приём, если нет — предлагает другое время. В конце пациент получает талон и идёт к врачу.


## Диаграммы

### BPMN-диаграмма
Файл: `lab1/diagrams/process.bpmn` и [process-bpmn.png](diagrams/process-bpmn.png)

Показывает весь процесс целиком: от прихода пациента до выдачи талона. Есть 2 шлюза XOR (для проверки "первый раз или нет" и "есть талон или нет") и 2 шлюза AND (для параллельных задач регистратора и медсестры). Позже я добавила туда задачу "Уточнить симптомы" — это было для части 4 задания.

### UML Activity Diagram
Файл: `lab1/diagrams/activity.drawio` и [UML Activity Diagram](diagrams/activity-uml.png)

Более детально показывает шаг "Проверка талонов". Сделала с дорожками (swimlanes) — Пациент, Регистратор и Система (БД), чтобы было видно, кто что делает. Есть решение (ромб) "Есть талон?" с двумя ветками. Позже я добавила туда задачу "Уточнить жалобы" — это было для части 4 задания.


### Sequence Diagram (Mermaid)
Файл: `lab1/docs/sequence.md`

Показывает обмен сообщениями между Пациентом, Регистратором и Системой. Есть блок alt для развилки "талоны есть / талонов нет".

### Flowchart (Mermaid)
Файл: `lab1/docs/flowchart.md`

Простая блок-схема алгоритма проверки талона: есть талон — записать, нет — предложить другое время.

## Выводы

Пока делала эту лабораторную, разобралась, чем отличаются разные способы описания одного и того же процесса — BPMN показывает общую картину и роли, UML Activity — больше про логику и ветвления, Sequence — кто кому что "говорит" по порядку, а Flowchart — просто алгоритм без лишних деталей.

С Git я уже сталкивалась в прошлом семестре на "Технологиях программирования", когда мы делали сайт и работали через Git Bash в VS Code. Так что по ходу работы многое вспомнилось: как клонировать репозиторий, как делать коммиты и пуш, команда `git diff`, `git log --oneline` для просмотра истории, `git config --global --list` для проверки настроек. Что-то всплывало прямо в процессе, когда снова вводила команды в терминале.

Но вот что реально стало понятнее только сейчас — как Git работает с разными типами файлов. Текстовые (.bpmn, .drawio, .md) он показывает построчно, видно каждую изменённую строку. А с картинками (.png) так не выйдет, там просто "Binary files differ" и всё. Раньше я об этом не задумывалась, потому что на сайте были в основном текстовые файлы.

Ещё поняла разницу между Git Bash и просто Git. Git — это сама система контроля версий, а Git Bash — это командная оболочка (терминал) для Windows, через которую удобно вводить команды. Можно работать и через другие интерфейсы (VS Code, GitKraken), но Git Bash даёт более полный контроль. В целом, материал был знаком, но эта лабораторная помогла систематизировать знания.

Отдельно хочу отметить работу с GitHub. В прошлом семестре мы не работали с ним в таком формате — все изменения хранились только локально. А сейчас я научилась связывать локальный репозиторий с удалённым и отправлять туда изменения командой `git push`. Это оказалось очень удобно: во-первых, все файлы хранятся в облаке и не потеряются, если что-то случится с компьютером. Во-вторых, к репозиторию можно получить доступ с любого устройства. В-третьих, на GitHub удобно смотреть историю изменений и сравнивать версии файлов прямо в браузере. В целом, материал был знаком, но эта лабораторная помогла систематизировать знания и освоить новый полезный навык.
